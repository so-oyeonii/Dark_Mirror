# Phase 2 확정 범위와 구현 결정

작성일: 2026-10-29

이 문서는 Phase 2의 구현 범위와 게스트 검사·결과 처리 기준을 구체화한다. 원본 제품·아키텍처 명세, `product/QUESTIONS.json`, 단계별 작업 문서는 보존한다. 아래 완료 기준은 검증할 목표이며, 이 문서만으로 구현 완료나 테스트 통과를 의미하지 않는다.

## 이번 단계에 포함

- `product/QUESTIONS.json`을 문항·차원·역문항 여부·문항 버전의 단일 출처로 사용한다. 현재 버전은 `draft-1.0`이며, 문항 원문을 별도 복사본에서 수정하지 않는다.
- `/test`에서 15문항을 한 번에 한 문항씩 보여주고, 1~5점 응답·진행 표시·이전/다음 이동을 제공한다. 이전 문항의 응답을 확인하고 수정할 수 있다.
- 진행 중 검사와 완료한 결과를 게스트 임시 저장소에서 복구한다. 모든 15개 응답이 유효해야 검사를 완료할 수 있다.
- 역채점 순수 함수, 5차원 결과 시각화·중립 설명·성찰 질문, `/result/[id]` 결과 화면과 `/me`의 임시 검사 이력을 제공한다.
- 재검사는 새 attempt와 새 UUID로 생성한다. 이전 완료 기록을 덮어쓰지 않는다.
- 관련 단위 테스트 최소 5개와 핵심 사용자 흐름 테스트를 추가하고 실제 검증 결과를 기록한다.

## 게스트 저장·만료·이력 정책

- 저장 위치는 현재 브라우저 탭의 `sessionStorage`다. 서버 계정에 저장하거나 기기·탭 간 결과를 동기화하지 않는다.
- 각 attempt의 시작 시각을 기준으로 고정 24시간 뒤 만료한다. 답변 수정, 새로고침, 검사 완료, 결과 재열람은 만료 시간을 연장하지 않는다.
- 진행 중 검사는 최대 1회, 완료 이력은 만료되지 않은 최근 20회까지 보관한다. 완료 시각을 기준으로 최근 기록을 유지하고 한도를 넘긴 가장 오래된 완료 기록은 제거한다.
- 활성 검사가 있으면 이어하기를 제공한다. 새로 시작하기는 기존 진행 내용을 버린다는 사실을 알린 뒤 새 UUID의 attempt로 바꾼다. 완료 이력은 별도로 유지한다.
- 저장 상태의 구조·문항 버전·응답 범위를 검증한다. 손상되었거나 지원하지 않는 버전의 데이터는 유효한 결과처럼 표시하지 않고 복구 불가 안내와 새 검사 시작 경로를 제공한다.
- 데이터 읽기·복구와 답변 저장·완료 시 만료 여부를 확인한다. 진행 중 만료되면 기존 attempt를 완료하거나 만료 시간을 갱신하지 않고 새 검사로 안내한다.
- 저장 실패·저장 차단 시 메모리 상태로 계속 사용할 수 있도록 하고, 새로고침하면 기록이 사라질 수 있음을 안내한다. 임시 데이터 초기화 시 검사 응답과 결과 이력도 정리한다.
- `sessionStorage`는 탭 종료 시 통상 정리된다. 브라우저가 세션을 복원할 가능성도 있으므로 24시간 만료 검사와 직접 초기화 기능을 함께 유지한다.

## 결과 URL과 비공개 범위

- `/result/[id]`는 현재 탭에서 보유한 해당 UUID의 완료 기록을 찾아 표시하는 경로다. 공개 공유 링크나 서버 조회 토큰이 아니다.
- URL에 닉네임, 출생정보, 문항 응답이나 점수를 넣지 않는다. 다른 브라우저·탭에서 결과를 조회할 수 있는 기능을 구현하지 않는다.
- 기록 없음, 만료, 초기화·삭제, 미완료 attempt는 결과처럼 렌더링하지 않는다. 이유를 설명하고 이력 또는 새 검사로 이동할 수 있게 한다.
- 브라우저에 남은 데이터가 해당 화면의 표시 근거다. 이 구조를 서버 접근 통제나 실제 인증이 구현된 것으로 설명하지 않는다.

## 채점 기준

- 원본 JSON에 정의된 15문항과 각 1~5 정수 응답만 채점한다. 누락·범위 밖 값·지원하지 않는 문항 조합으로 완료할 수 없다.
- 역문항은 `6 - 원래 응답`, 일반 문항은 원래 응답을 사용한다.
- 각 차원의 수정 응답 3개 평균에 `((평균 - 1) / 4) * 100`을 적용한다. 최종 차원 점수는 소수 첫째 자리로 표시한다.
- 닉네임, MBTI, 생년월일·시간·시간대와 사주 정보는 점수 계산에 사용하지 않는다. 문항 응답과 점수 방향만 결과의 근거로 사용한다.
- 0~100은 각 차원 응답을 변환한 척도다. 위험 확률, 학대 취약성 백분율, 타인 대비 백분위, 심리검사 규준 점수로 표현하지 않는다.
- 높은 점수를 우수함·정상·안전함으로, 낮은 점수를 열등함·이상·위험함으로 구분하지 않는다. 종합 점수나 등급·진단·검증되지 않은 캐릭터 유형을 새로 만들지 않는다.
- 문항 버전과 채점 버전을 기록해 후속 변경에 대비한다. 완료 기록은 별도의 재검사로 대체하지 않는 한 과거 응답 기록으로 유지한다.

## 한국어 문구 제안

응답 척도는 다음과 같이 사용한다.

| 값 | 레이블 |
|---|---|
| 1 | 전혀 그렇지 않다 |
| 2 | 그렇지 않은 편이다 |
| 3 | 보통이다 |
| 4 | 그런 편이다 |
| 5 | 매우 그렇다 |

검사 시작 안내: “최근의 나를 떠올리며 가장 가까운 답을 골라주세요. 정답은 없으며, 상황에 따라 답이 달라질 수 있어요.”

결과 공통 고지: “이번 응답에서 나타난 경향을 정리했어요. 점수는 좋고 나쁨이나 실제 관계의 안전성을 뜻하지 않으며, 검증된 심리검사나 진단 결과가 아닙니다.”

| 차원 | 중립 설명 | 성찰 질문 |
|---|---|---|
| 경계 설정 | 부담스러운 부탁이나 의견 차이가 있을 때 자신의 의사를 표현하는 경향을 살펴봐요. 점수가 높을수록 이번 응답에서 경계를 표현하는 쪽에 가까웠어요. | 최근 내 의사를 편하게 표현했던 상황과 어려웠던 상황은 어떻게 달랐나요? |
| 인정 추구 | 선택과 관계에서 다른 사람의 인정이나 평가를 얼마나 중요하게 느끼는지 살펴봐요. 점수가 높을수록 이번 응답에서 타인의 인정을 중요하게 여기는 쪽에 가까웠어요. | 다른 사람의 반응을 잠시 내려놓는다면, 나는 어떤 선택을 하고 싶나요? |
| 갈등 회피 | 불편한 문제나 의견 충돌이 생겼을 때 대화를 미루거나 의견 표현을 줄이는 경향을 살펴봐요. 점수가 높을수록 이번 응답에서 갈등을 피하는 쪽에 가까웠어요. | 미뤄 둔 대화가 있다면, 지금 내 상황에서 꺼낼 수 있는 작은 주제는 무엇인가요? |
| 관점 수용 | 의견이 다른 사람의 상황과 생각을 고려하는 경향을 살펴봐요. 점수가 높을수록 이번 응답에서 다른 관점을 고려하는 쪽에 가까웠어요. | 상대의 입장을 이해하면서도 지키고 싶은 내 생각이나 필요는 무엇인가요? |
| 불확실성 대처 | 상대의 의도나 상황이 분명하지 않을 때 여러 가능성을 열어두는 경향을 살펴봐요. 점수가 높을수록 이번 응답에서 모호함을 견디는 쪽에 가까웠어요. | 아직 알 수 없는 부분과 지금 확인해 볼 수 있는 부분을 나눈다면 무엇이 남나요? |

임시 저장 안내: “이 검사는 현재 탭에 임시 저장되며, 시작한 시각부터 24시간 뒤 만료돼요. 결과 주소는 공개 공유 링크가 아니에요.”

저장 실패 안내: “이 브라우저에서 임시 저장을 사용할 수 없어요. 검사는 계속할 수 있지만 새로고침하면 응답과 결과가 사라질 수 있어요.”

## 이번 단계에서 제외

실제 이메일 인증, Supabase DB 저장·RLS 기반 계정 이력, 게스트 결과의 계정 이전, 실제 AI 대화, 궁합 보고서, 공개 공유 카드·링크, 사주 계산은 아직 제공하지 않는다. 환경변수가 채워져도 해당 기능을 자동 활성화하지 않는다. 기존 Phase 1 인증·DB 안내와 후속 연동 게이트를 유지한다.

## 사용자가 직접 해야 할 일

Phase 2의 로컬 게스트 검사 구현·검증을 위해 사용자가 지금 제공해야 할 키나 별도 설정은 없다.

후속 실제 서비스 연동 시에는 사용자 소유 서비스 계정과 프로젝트 설정, 실제 인증 설정, 도메인 선택·소유권 확인, 공개 출시의 개인정보·보존·삭제 정책 결정이 필요하다. 필요한 시점에 구체적인 항목을 안내하며, 이 문서를 이유로 지금 비밀키나 인증정보 입력을 요구하지 않는다.

## Phase 2 완료 기준

- [ ] 원본 JSON에서 15문항·5차원·각 차원 3문항을 읽고 문항 원문을 보존한다.
- [ ] 한 문항씩 표시하며 5점 척도, 이전·다음, 선택 상태·진행 정보를 키보드와 360px 화면에서 사용할 수 있다.
- [ ] 15문항 모두 유효하게 답하기 전에는 완료할 수 없다.
- [ ] 역채점과 차원별 0~100 변환·소수 첫째 자리 표시를 결정적으로 검증한다.
- [ ] 이전 이동·수정·새로고침 복구와 저장 실패 안내를 확인한다.
- [ ] 시작부터 고정 24시간 만료가 답변 수정·완료·재열람으로 연장되지 않는다.
- [ ] 진행 중 1회·완료 최근 20회 제한과 재검사 새 UUID 생성, 기존 완료 기록 보존을 확인한다.
- [ ] 정상 결과·기록 없음·만료·미완료·손상 데이터 상태를 구분한다.
- [ ] 결과의 5차원 시각화와 설명·성찰 질문·비검증 및 비진단 고지를 제공한다.
- [ ] 프로필 정보가 채점에 영향을 주지 않고, 결과 URL을 공개 공유로 설명하지 않는다.
- [ ] 최소 5개 단위 테스트와 핵심 화면 흐름 검증을 실행한다.
- [ ] lint, typecheck, test, build의 실제 결과와 실행하지 못한 검증의 이유를 기록한다.
