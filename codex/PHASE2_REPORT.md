# Phase 2 구현·검증 기록

작성일: 2026-10-29 (Asia/Seoul)

## 구현 범위

로그인 없이 15문항을 진행하고, 다섯 차원의 결과와 검사 이력을 확인할 수 있도록 기존 Phase 1 앱을 확장했다. 기존 의존성을 사용했으며 새 패키지를 추가하지 않았다.

- 원본 `product/QUESTIONS.json`을 유일한 문항 출처로 사용. 텍스트·역문항·문항 버전 `draft-1.0`을 변경하지 않음.
- 1문항씩 5점 선택, 이전/다음, 미응답 이동 제한, 15문항 완료 전 결과 생성 차단.
- 응답과 현재 문항의 임시 저장·새로고침 복구, 진행 중 재시작 확인.
- 역문항은 `6 - raw`, 차원별 3문항 평균을 0~100으로 변환하고 소수 한 자리로 반올림. 프로필·MBTI·출생정보 불사용.
- 다섯 차원의 가로막대·숫자·중립 설명·성찰 질문, 비검증·비진단 고지. 총점·우열·취약성 예측 없음.
- 새 검사마다 UUID를 생성. 완료 결과 불변, 중복 완료는 동일 ID 반환. 완료 기록 최근 20개와 진행 중 1개를 유지.
- 검사 시작부터 고정 24시간 뒤 만료. 수정·완료·새로고침으로 연장되지 않음. 열린 검사·결과 화면도 만료 시 정리.
- 검사 이력의 개별/전체 삭제. 프로필 초기화는 검사 기록과 구분.
- 저장소 차단·손상 데이터·버전 불일치·쓰기/삭제 실패 처리, 메모리 fallback 및 잔존 가능성 안내.
- 온보딩 저장/건너뛰기 후 `/test`로 연결. 랜딩·마이·인증 안내·준비 중 화면의 문구를 현재 범위에 맞춰 갱신.

## 검증 결과

| 검증 | 결과 |
|---|---|
| `npm run lint` | 통과, 오류·경고 없음 |
| `npm run typecheck` | 통과 |
| `npm test` | 5개 파일, 총 55개 통과 (Phase 2 추가 27개) |
| `npm run build` | Webpack 프로덕션 빌드 통과, `/result/[id]` 동적 경로 포함 |
| `npm run test:e2e` | Chromium 360×800 모바일·1280×900 데스크톱, 총 30개 통과 |
| 자동 접근성 | 기존 7개 화면 및 활성 검사·완료 결과·이력·결과 없음 상태의 axe 검사 위반 0건 |

채점 기준값: 모두 1 응답 시 차원별 33.3, 모두 3이면 50.0, 모두 5이면 66.7. 정방향5/역방향1은 100, 그 반대는 0. 미완료·알 수 없는 문항 ID·문자열·소수·범위 밖 값은 거부한다.

브라우저 검증은 다음을 포함한다.

- 질문 선택, 이전 이동, 답변 수정, 새로고침 복구, 전체 완료.
- 재검사 결과 ID 분리, 새 탭 직접 URL에서 기록 없음, 삭제 후 원래 URL에서도 결과 없음.
- 저장소 차단 상태에서 완료 가능, 새로고침 시 메모리 결과 소실 안내.
- 가상 시계로 진행 중/완료 결과의 고정 만료 확인.
- 실제 검사 흐름에서 POST/PATCH/PUT/DELETE 요청 없음 및 페이지 런타임 오류 없음.
- 360px 가로 넘침, 라디오·결과·이력의 자동 접근성 검사.

기획·UX·QA 담당이 분담했다. 독립 정적 검수에서 탭 복제 시 `sessionStorage`가 복사될 수 있으므로 “다른 탭에서는 열 수 없다”는 단정 문구를 수정했다. 모바일 캡처 검토로 활성 검사 화면의 상단 안내를 축약했다.

자동 접근성 검사는 전체 WCAG 준수나 수동 스크린리더 검증을 대신하지 않는다. 실제 모바일 기기, Safari, Firefox는 이번 범위에서 확인하지 않았다.

## 실행과 직접 확인

```powershell
npm run dev
```

`http://127.0.0.1:3000/test`에서 시작한다. 키 없이 실행된다. 검사는 이름이나 출생정보 없이 진행할 수 있다. E2E 재실행은 `npm run build` 후 `npm run test:e2e`이며, 필요 시 `npx playwright install chromium`을 먼저 실행한다.

검증용 화면 캡처는 git 제외 경로 `test-results/phase2-*-question.png`, `test-results/phase2-*-result.png`에 있다. 결과 캡처는 자동 테스트가 모든 문항에 중간값을 선택한 예시이며 사용자 본인의 검사 결과가 아니다.

## 한계와 다음 작업

현재는 로컬 데모다. 결과 URL만으로 서버에서 개인 결과를 내려주지 않으며, 임시 기록이 없는 브라우저·탭에서는 결과가 없다. 브라우저의 탭 복원·복제로 기록이 남거나 복사될 수 있다. 로그인·DB 영구 저장·AI·궁합·공개 공유·사주 계산·배포는 아직 제공하지 않는다.

다음 실서비스 작업은 인증·DB 저장 연동이다. Supabase 매직 링크/콜백·세션 갱신, RLS·소유권, 요청 제한, 명시적 게스트 데이터 이전을 검증한 뒤 실제 AI·궁합 단계와 연결한다.

지금 사용자가 직접 제공할 설정은 없다. 실제 연동 단계에서는 서비스 계정 로그인·프로젝트 설정·키·사용 예산을 확인하고, 출시 전에 도메인·이용 연령·개인정보 보존/삭제 정책·배포 여부를 결정한다. 비밀키는 채팅이 아닌 로컬 환경변수 또는 배포 서비스의 비밀 설정으로 다룬다. PWA/스토어 앱 출시는 별도 범위다.
