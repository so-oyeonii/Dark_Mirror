# DARK MIRROR — 다음 작업과 완료 기준

2026-10-29. 원본 `codex/tasks/01~05`와 제품 명세를 변경하지 않고 현재 구현과 남은 일을 구분한 실행 계획이다.

## 최신 실행 순서 — 로그인 전 기능 우선

사용자 요청으로 로그인·마이페이지 실연동보다 게스트 기능을 먼저 완성한다. **사주 엔진 검증 → 내 사주·MBTI 결과 → 카드 확장 → 실제 AI 연결 준비 → 로그인·서버 저장 → 실제 2인 궁합 → 공개 공유·출시** 순서다. 아래 번호는 작업 영역 구분이며 이 최신 실행 순서를 우선한다.

이번에 사주 엔진, 사주·MBTI 화면/카드, 독립 검수의 별도 세션 3개를 생성해 착수했다. 현재 대화가 총괄한다. 담당 파일·공통 계약·실제 세션 ID는 `PREAUTH_SESSIONS.md`에 기록했다. 사주 엔진과 UI는 합의된 타입으로 병행 개발하되 검증되지 않은 계산 결과를 사용자에게 확정 표시하지 않는다.

후속 진행: 세션별 사주 엔진·프로필·카드 구현이 도착해 통합했다. `/profile`에서 1989~2026년 Asia/Seoul 범위의 로컬 명식·오행과 MBTI 고정 성찰 문구를 제공한다. 시간 미상은 시주 제외, 절입 경계는 확정 거절한다. 이는 사주 전 범위/모든 관법이나 개인별 AI 운세 해석의 완성을 뜻하지 않는다. 통합 실행 결과는 `PREAUTH_REPORT.md`에 기록한다. 다음 구현은 실제 AI 연결이며 현재는 `AI_INTEGRATION_PREP.md`의 준비 계획만 있다. 실로그인·계정 저장·실제 2인 초대·공개 공유·배포는 계속 후속 범위다.

로컬 데모의 완료가 운영 단계 전체의 완료를 뜻하지 않는다. 특히 가상 A/B는 실제 상대의 동의를 받은 것이 아니고, 로컬 삭제는 계정 탈퇴나 원격 Storage 삭제가 아니다.

## 1. 인증 및 계정 저장 연결

사용자 준비: 본인 서비스 계정으로 Supabase 프로젝트, 인증 이메일 발신과 개발/운영 리디렉션 설정. 비밀값은 채팅 대신 환경변수에 입력한다.

개발 작업: 서버 세션 검증·매직 링크 콜백·갱신·로그아웃, 게스트 기록 이전 동의와 중복 방지, 서버 검증 채점/저장. 원본 0001과 보완 0002를 검증용 프로젝트에 적용하고 실제 A/B/익명 JWT로 RLS를 확인한다. 완료 처리와 답안 수정은 부모행 잠금·트랜잭션으로 정합성을 보장한다.

완료 기준: A는 B의 행을 조회/변경할 수 없고, 점수·턴 상태·생성 사주 값을 클라이언트가 위조할 수 없다. 서버 저장 결과가 재로그인·다른 기기에서 재현되고, 동의하지 않은 게스트 정보는 이전하지 않는다.

## 2. 실제 대화 연결

사용자 준비: LLM 서비스 계정/키, 월·일 예산. 현재 고정 대사 데모는 유지한다.

개발 작업: 원본 ai/prompts 버전 관리, JSON 출력 검증, 타임아웃/실패 복구, DB 기반 멱등성·5턴 상태 전이·분산 요청 제한·비용 상한. 위험 상황에서는 역할극을 종료하며 악성 지시/개인정보를 모델 제어 지시로 취급하지 않는다.

완료 기준: 실제 모델 응답을 검증하고 오류·재시도에 중복 과금/턴 증가가 없으며 중단 이후 모델 호출을 하지 않는다. 모델은 진단·상대방 판정·모욕 강화를 제공하지 않는다. 안전 분기는 정규식만으로 충분하다고 간주하지 않는다.

## 3. 실제 두 사람 궁합 및 사주

사용자 준비: 두 테스트 계정. 사주 제공 범위·검증 엔진 선택은 구현 전에 결정한다.

개발 작업: 인증된 초대 생성/수락을 서버 트랜잭션으로 처리하고 해시만 저장한다. 72h·일회 사용·참여자·양측 동의 교집합을 매번 검증한다. 철회 시 보고서와 연결 카드 접근을 함께 차단한다. 음력/윤달/절기/시간대 엔진은 검증 전 활성화하지 않는다.

완료 기준: 두 계정·제3자·익명·동시 수락·철회/조회 경쟁 테스트 통과. 원본 답변·생일·대화를 공유하지 않고, 종합 궁합 퍼센트를 만들지 않는다. 사주·MBTI는 점수와 분리한다.

## 4. 공개 공유 및 계정 삭제

개발 작업: 공개 payload 허용 목록, 서버 토큰/해시·만료·철회 조회, 비공개 Storage. 탈퇴 시 노출 차단 후 파일 경로를 내구성 있는 삭제 작업에 확보하고 DB cascade와 Storage 정리를 재시도 가능하게 실행한다. 실패 시 '탈퇴 완료'로 표시하지 않는다.

완료 기준: 삭제·철회 후 공개 조회 거부, Storage 정리 실패/재시도/중복 요청 검증. 이미 다운로드된 파일을 회수할 수 없다는 고지는 유지한다.

## 5. 공개 출시 및 앱 형태

사용자 결정: 도메인, 대상 연령, 개인정보 보존/삭제 정책, 공개 배포 승인. 상세 게이트는 INTEGRATION_CHECKLIST.md 참조.

개발 작업: 실제 모바일 Safari/Chrome, 키보드·스크린리더 수동 QA, 운영 보안 헤더/CSP·캐시·로그의 민감정보 제거, 알림/모니터링·백업/복구와 장애 대응, 최종 배포 검증.

현재 제공물은 모바일/PC 웹이다. 설치형 PWA와 앱스토어 앱은 별도 후속 범위이며 자동으로 제공되지 않는다. PWA를 선택하면 설치/업데이트/오프라인/민감 데이터 캐시 정책을 설계하고, 스토어 앱을 선택하면 패키징·개발자 계정·심사를 추가한다.

## 진행 원칙

외부 계정 설정 전에도 소스·SQL·검증을 준비하되, 키를 넣는 것만으로 미검증 기능을 켜지 않는다. 실제 연결마다 위 완료 기준을 통과하고 사용자에게 실행 결과와 남은 제한을 보고한다. 기존 기획·문항·시나리오 원본은 보존한다.
