# Phase 1 확정 범위와 구현 결정

작성일: 2026-10-29

이 문서는 구현 전 기획 검토에서 확인한 공백을 Phase 1 범위 안에서 보완한다. 원본 `AGENTS.md`, 제품·아키텍처 명세, 단계별 작업 문서는 보존한다. 아래 완료 기준은 검증할 목표이며, 이 문서 자체가 구현 또는 테스트 통과를 의미하지 않는다.

## 이번 단계에 포함

- Next.js App Router, TypeScript strict, Tailwind 기반 한국어 모바일 우선 앱.
- 색상·타이포그래피·간격·포커스 등 디자인 토큰과 접근 가능한 공통 UI.
- 랜딩(`/`), 온보딩(`/onboarding`), 계정 안내(`/auth`), 마이(`/me`).
- 홈·테스트·AI 체험·궁합·마이의 하단 내비게이션. 후속 기능인 `/test`, `/simulation`, `/match`는 해당 기능이 아직 준비 중임을 설명하는 화면으로 연결한다.
- Zod 입력 검증, 게스트 임시 프로필, Supabase 클라이언트/서버 팩토리, 환경변수 예시와 비밀정보 제외 설정.
- 의미 있는 오류·로딩·빈 상태, 기본 단위 테스트와 화면 이동 테스트, 실행 안내.

## 이번 단계에서 완료로 표시하지 않는 기능

15문항 검사·채점·결과, 실제 AI 대화, 2인 궁합 초대·보고서, 공유 PNG, 서버 결과 이력·이전·삭제, 실제 이메일 로그인, 사주 계산은 후속 작업이다. 준비 중 화면이나 데모 화면을 실제 기능 완료로 표현하지 않는다.

## 온보딩과 게스트 상태

- 프로필 전체를 건너뛰고 익명 게스트로 진행할 수 있다. 닉네임은 입력한 경우에만 2~20자 조건을 적용한다. MBTI와 출생정보도 선택 입력이다.
- 게스트 데이터는 현재 브라우저 탭의 `sessionStorage`에 보관한다. 저장한 임시 상태는 새로고침 후 복구할 수 있으며, 서버 계정에 저장된 기록으로 표현하지 않는다.
- 임시 데이터에 생성 시점과 만료 시점을 기록하고 최대 24시간의 TTL을 적용한다. 읽기·복구 시 만료 여부를 확인하여 오래된 상태를 폐기한다. 저장 데이터의 구조도 검증하고, 손상되었거나 지원하지 않는 버전이면 안전하게 초기화한다.
- 사용자가 직접 임시 데이터를 초기화할 수 있다. `sessionStorage` 특성상 탭 종료 시 통상 정리되지만, 브라우저 세션 복원 동작은 브라우저에 따라 다를 수 있으므로 TTL 검사도 유지한다.
- 브라우저가 저장을 차단하거나 저장 과정이 실패하면 메모리 상태로 계속 사용할 수 있다. 이때 현재 화면에서만 유지되며 새로고침하면 사라질 수 있음을 한국어로 안내한다.
- 후속 계정 연결 시 게스트 데이터를 자동으로 업로드하지 않는다. 명시적 이전 확인을 거쳐야 한다.

## 출생정보와 날짜 검증

- 양력은 실제 존재하는 날짜인지 검사한다. 출생시간 미상은 별도 상태로 유지하며 임의의 시간으로 채우지 않는다.
- 음력 원본은 연·월·일, 윤달 여부, 시간대 등 입력값으로 보존한다. 음력 원본과 변환된 양력 날짜는 서로 다른 데이터다. 음력 값을 양력 날짜 필드에 그대로 넣지 않는다.
- Phase 1에서는 음력 날짜의 기본 형식·범위 검증과 달력 엔진에 의한 실제 날짜 검증을 구분한다. 검증된 변환 엔진이 연결되지 않았으므로 음력 변환을 수행하거나 실제 날짜 검증 완료를 주장하지 않는다.
- 검증·변환 대기 상태와 사주 `계산 준비 중`을 표시한다. 출생정보만으로 명식·시주·운세를 꾸며내지 않는다.

## 인증·DB 연결 상태

- Phase 1은 Supabase 클라이언트/서버 팩토리와 미연결 안내를 제공한다. 환경변수에 키가 있다는 이유만으로 실제 인증 또는 DB 읽기·쓰기를 자동 활성화하지 않는다.
- `/auth`는 현재 인증 연동 상태를 설명한다. 실제 이메일을 보내지 않았다면 발송 성공을 표시하지 않고, 가짜 사용자나 로그인 세션을 생성하지 않는다.
- `/me`는 게스트 상태와 입력한 임시 프로필을 확인·초기화하는 범위를 제공한다. 서버 저장·이력·계정 삭제가 구현된 것으로 표시하지 않는다.
- 비밀키는 서버 전용으로 두고 `.env.local`을 Git에서 제외한다. `.env.example`에는 빈 플레이스홀더만 제공한다.

## 후속 연동 게이트

실제 서비스 기능을 켜기 전에 별도 인증·저장 연동 작업을 수행한다.

1. 실제 Supabase 프로젝트 설정, 인증 콜백·리디렉션, 로그인·로그아웃·실패 흐름을 검증한다.
2. DB 스키마와 RLS를 점검하고, 다른 사용자의 데이터 접근 거부를 검증한다. 서버에서도 소유권을 검사하며 클라이언트가 보낸 사용자 ID를 신뢰하지 않는다.
3. 게스트 데이터 이전 동의 UI와 서버 입력 검증, 중복 이전 방지, 이전 실패 시 복구 흐름을 구현한다.
4. 필요한 쓰기 API의 요청 제한과 상태 전이를 검증한다. 이 게이트를 통과하기 전에는 실제 DB 접근을 활성화하지 않는다.
5. 실제 AI와 궁합은 각 단계의 인증·안전·동의 조건을 추가로 충족해야 한다. 공개 출시 전에는 삭제·보존·공유 철회 정책과 전체 출시 차단조건도 검증한다.

## Phase 1 완료 기준

- [ ] 360px 이상에서 가로 넘침 없이 사용할 수 있고, 키보드 포커스·레이블·읽기 대비가 제공된다.
- [ ] 랜딩에서 온보딩으로 이동하고 개인정보 없이 건너뛸 수 있다.
- [ ] 입력 오류를 한국어로 안내하고 선택 항목의 미입력을 허용한다.
- [ ] 게스트 상태의 새로고침 복구, 24시간 만료, 손상 데이터 처리, 직접 초기화, 저장 실패 시 메모리 fallback을 확인한다.
- [ ] 음력 원본과 양력 변환 결과를 혼동하지 않고 사주 계산 미연결 상태를 표시한다.
- [ ] 5개 하단 탭이 404 없이 해당 화면으로 연결되고 준비 중 기능을 구분한다.
- [ ] 인증정보 없이 앱이 실행되며 실제 로그인·저장 성공을 꾸며내지 않는다.
- [ ] 의미 있는 단위 테스트와 핵심 이동 테스트를 실행하고 실패를 수정한다.
- [ ] lint, typecheck, test, build의 실제 결과를 기록한다. 실행하지 못한 검증은 이유와 함께 미실행으로 보고한다.
- [ ] 변경 파일, 실행 방법, 실제 작동 범위와 후속 연동 조건을 사용자에게 전달한다.
