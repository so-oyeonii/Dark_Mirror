# 실제 AI 연결 준비 — 총괄 담당

2026-10-29. 이번 별도 세션 작업의 우선 대상은 사주 계산과 게스트 결과/카드다. 이 문서는 그 다음 실제 AI 연결의 경계와 작업 순서를 정리한다. 실제 제공자를 선택/설치/호출한 결과나 구현 완료 보고가 아니다.

## 현재 재사용 가능한 코드

- `src/lib/simulation.ts`: 5턴 요청·출력·피드백 스키마, 상태 전이, 종료 및 제한적인 안전 분기. 현재 결과는 고정 문구다.
- `src/server/demo-simulation.ts`: 개발 전용 단일 프로세스 capability·중복 요청·요청 제한. 운영 인증/분산 저장소가 아니다.
- `src/app/api/demo/simulation/route.ts`: development 및 loopback 제한, 동일 Origin, 8KiB, no-store. 운영에서 활성화하거나 live 모델 호출을 끼워 넣지 않는다.
- `ai/prompts/SYSTEM_RULES.md`, `SIMULATION.md`, `FEEDBACK.md`: 원본 프롬프트. 템플릿의 사용자 답변/기록은 신뢰된 지시가 아닌 별도 데이터 메시지로 처리해야 한다.

## 후속 구현 단위

1. 사용자가 선택한 제공자/모델/사용 예산과 실행 환경을 확인하고 공식 SDK·문서 기준으로 별도 서버 어댑터를 구현한다. 키를 프런트엔드에 넣거나 자동 검색·출력하지 않는다. Vercel을 선택할 때만 해당 AI 연동 경로와 CLI 안내를 적용하며 플랫폼 변경을 강제하지 않는다.
2. 모델 입력에는 필요한 현재 시나리오/대화 범위만 넣고 출생정보·닉네임·프로필을 보내지 않는다. 프롬프트의 버전과 해시를 서버에 기록한다. 로그에는 원문·토큰을 남기지 않는다.
3. 외부 호출 전에 종료/안전/횟수/비용을 검사한다. 요청 ID와 입력 해시를 내구성 저장소에 묶어 같은 요청을 재과금/중복 처리하지 않는다. 처리 중 lease/시간초과/충돌/늦은 응답/취소를 상태 전이로 다룬다. 로컬 Map으로 분산 운영을 흉내 내지 않는다.
4. 외부 응답의 길이·JSON·선택지·서버 턴 상태를 검증한다. 서버의 stop/completed가 우선하고 모델이 턴을 추가하거나 다시 역할극을 시작하지 못하게 한다. 실패는 실패로 표시하며 고정 데모를 실제 AI 응답처럼 대체하지 않는다.
5. 전송·타임아웃·잘못된 JSON·429/5xx·취소·중복·비용 상한 테스트를 작성한다. 실제 키가 없으면 네트워크 테스트 대역으로 검증하되 live 검증 미실행을 명확히 보고한다.
6. 로그인 전 실제 AI 체험을 열 경우에도 별도의 서버 검증 게스트 세션과 남용·요청·비용 제한이 필요하다. 이러한 보호와 운영 저장소가 준비되지 않으면 실제 호출 UI를 활성화하지 않는다.

사용자 계정 로그인/키 입력/비용 설정이 필요한 시점에만 구체적으로 요청한다. 지금 생성한 사주·화면·검수 세션의 작업에는 API 키가 필요 없다.
